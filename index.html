📦 6 Phases of Compiler

1. Lexical Analysis: char stream → tokens (token-name, attr-val). Removes whitespace/comments. Uses RE.

2. Syntax Analysis: tokens → parse tree. Uses CFG. Reports syntax errors.

3. Semantic Analysis: type checking, scope checking. Uses symbol table. Produces annotated tree.

4. ICG: parse tree → TAC / IR. Machine-independent.

5. Code Optimization: improve TAC. Faster/smaller code. Machine-independent.

6. Code Generation: TAC → target machine code. Register allocation.

+ Symbol Table: Shared data structure. Stores identifiers, types, scope, address.

🔤 RE / NFA / DFA Quick Reference

RE Operators: r|s (union), rs (concat), r* (Kleene), r+ (≥1), r? (0 or 1), [a-z] (class)

Thompson's NFA: RE→NFA. Each operator adds states. ε-transitions allowed.

Subset Construction (NFA→DFA): DFA state = set of NFA states. Start = ε-closure(q0). Transition = ε-closure(move(S,a)).

DFA minimisation: Hopcroft algorithm. Partition into {accept} and {non-accept}, then refine.

Identifier RE: letter(letter|digit)* where letter=[a-zA-Z_], digit=[0-9]

Integer RE: digit+ = [0-9]+

Float RE: digit+(.digit+)?(E(+|-)?digit+)?

📥 Input Buffering — Two Buffer Schema

Problem: Single buffer requires 2 reads per char (read char, check if boundary).

Solution: Two buffers of N chars each. Sentinel EOF at end of each half.

Pointers: lexemeBegin = start of current lexeme. forward = current scan position.

Trick: forward hits eof → reload other buffer; hits EOF → end of file.

Pair Buffer Example: "pos=i**j" — forward scans to first *, then second *. If * is hit at boundary of buffer, reload happens transparently.

🎯 FIRST & FOLLOW — Complete Rules

FIRST(X):

  • If X=terminal: FIRST(X)={X}
  • If X→ε: add ε to FIRST(X)
  • If X→Y₁Y₂...Yₙ: add FIRST(Y₁)−{ε}; if ε∈FIRST(Y₁), add FIRST(Y₂)−{ε}; ... if ε in all, add ε

FOLLOW(A):

  • FOLLOW(S) = {$} (start symbol)
  • If A→αBβ: add FIRST(β)−{ε} to FOLLOW(B)
  • If A→αB or ε∈FIRST(β): add FOLLOW(A) to FOLLOW(B)

📋 LL(1) Parse Table Algorithm

For each production A→α:

  1. For each terminal a ∈ FIRST(α): add A→α to M[A,a]
  2. If ε ∈ FIRST(α): for each b ∈ FOLLOW(A): add A→α to M[A,b]
  3. If ε ∈ FIRST(α) and $ ∈ FOLLOW(A): add A→α to M[A,$]

Parsing algorithm: Stack has grammar symbols. Pop X, look at input a:
— X=terminal: if X=a, pop & advance input; else ERROR
— X=NT: use M[X,a] to push production body in reverse order
— X=$: if input=$, ACCEPT; else ERROR

GOTO: transitions on non-terminals. ACTION: transitions on terminals.

Shift-Reduce conflict: item has both •a and [A→α•] in same state.

Reduce-Reduce conflict: two different complete items [A→α•] and [B→β•] in same state.

🌳 SDD — Syntax Directed Definitions

Synthesized attribute: computed from children. Flows UP. Can use bottom-up parser.

Inherited attribute: computed from parent/siblings. Flows DOWN. Needs top-down evaluation.

Dependency graph: edge from A.attr to B.attr if B.attr is computed using A.attr. If acyclic → can evaluate.

S-attributed SDD: all synthesized. Evaluated in postorder (bottom-up).

L-attributed SDD: synthesized + inherited where inherited comes from left siblings or parent only.

Key exam task: Write semantic rules for each production, draw annotated parse tree, show attribute values at each node.

💡 DAG vs AST vs TAC

AST (Abstract Syntax Tree): tree, no node sharing. n expressions = n nodes.

DAG: like AST but common subexpressions share nodes. Fewer nodes = more efficient code.

TAC: linear sequence. At most 3 addresses per instruction. Types: x=y op z | x=op y | x=y | goto L | if x goto L | x=y[i] | x[i]=y

Quadruples: (op, arg1, arg2, result) — 4 fields. result stored explicitly.

Triples: (op, arg1, arg2) — no result field; result = position number (0), (1), ... Code optimization harder.

Indirect triples: Triples + pointer array. Allows reordering without changing triples. Best for optimization.

LR / LL(1) MASTER SECTION
Fastest shortcuts, conflict detection, full solved examples from scratch.
⚡ SPEED TRICKS FIRST: start from terminals and work up. FOLLOW: start from S=$, propagate right. For LR(0): only state with dot at END is reduce state. For conflicts: if FOLLOW(A) overlaps with any SHIFT terminal in same state = shift-reduce conflict.

🏎️ Fast FIRST/FOLLOW Method

  1. List all productions in a table
  2. FIRST: For each NT, look at first symbol of each production body. If terminal → add it. If NT → recurse. If production is A→ε → add ε.
  3. Repeat until no changes (fixed point)
  4. FOLLOW: Place $ in FOLLOW(start). Then scan all productions for β after each NT.
  5. If A→αBβ and β≠ε: add FIRST(β)−{ε} to FOLLOW(B)
  6. If A→αB or (ε∈FIRST(β)): add FOLLOW(A) to FOLLOW(B)

🎯 Conflict Detection Cheatsheet

Shift-Reduce Conflict: In state I, there's both [A→α•aβ] AND [B→γ•] where a ∈ FOLLOW(B).
Can usually resolve by: shift preferred over reduce (for operators).
Reduce-Reduce Conflict: In state I, [A→α•] AND [B→β•] both present, AND FOLLOW(A)∩FOLLOW(B)≠∅.
This is a more serious conflict — grammar may not be SLR(1).

Quick check: Count complete items in each state. If 0 or 1 → no conflict from reduces. If 2+ → check FOLLOW overlap.

✅ SOLVED EXAMPLE 3 — CLR(1) / LR(1)

I2 = GOTO(I0, m): [P→m•PnP, $]
  Closure adds: [P→•mPnP, n], [P→•nPmP, n], [P→•, n]

⚠️ Partial Marks Maximisation

  • For LR problems you can't finish: Show I0 fully, then list at least 3-4 more states. Draw the DFA structure. Partial credit for each correct state (≈0.5M per state).
  • For parse table: Even if FIRST/FOLLOW is wrong, fill the table consistently with your values. Examiner checks METHOD, not just answer.
  • For TAC: Write the code structure correctly (with labels and gotos), even if array offset computation is wrong. Structure = 2M, computation details = 1M.
  • For DAG: Draw the tree first (AST), then convert to DAG by identifying shared nodes. Even partial DAG with 2-3 shared nodes = partial credit.
  • For 2M definition questions: Give definition + 1 example always. Definition alone = 1M, with example = 2M.
  • For LEX programs: Write the structure (%%...%%) even if the RE is wrong. Program structure = 1M.

What examiners reward

  • Clearly labelled diagrams (start state, accept state)
  • Showing working steps (not just final answer)
  • State explicitly: "Grammar IS/IS NOT LL(1) because..."
  • Naming which rule you're applying (e.g., "applying closure rule")
  • Neat tables with clear headers
  • Parsing trace in a table format

How to handle difficult LR

  • First write all items for I0 — you get marks for this alone
  • Compute GOTO(I0, X) for each symbol — partial states = partial marks
  • If stuck on closure: write "Closure of state Iₙ includes:" then list what you know
  • For the table: fill shift entries (easier) first, then reduce
  • Always state number of reduce states explicitly
  • A complete I0 + partial DFA = 2-3/5 marks
